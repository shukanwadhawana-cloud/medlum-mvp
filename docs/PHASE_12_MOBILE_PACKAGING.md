# Phase 12 — Android + iOS native packaging

Phase 12 packages MedLum Health as a Capacitor mobile application for Android and iOS. It uses the existing MedLum web application and production API boundary rather than creating a second clinical frontend.

## Architecture

- Capacitor app ID: `com.medlum.app`
- App name: `MedLum Health`
- Native platforms: Android and iOS
- The native WebView loads the HTTPS MedLum origin configured through `CAPACITOR_SERVER_URL`.
- Manual workflow runs accept an `app_url` input. The default is `https://medlumhealth.com`; `vars.CAPACITOR_SERVER_URL` can override the default for automated runs.
- `CAPACITOR_BUILD=true` enables Next static-export mode only for environments that need a local web bundle. The current native packages use the deployed origin so authenticated, server-backed clinical workflows continue to run on the MedLum service.
- The small local `out/index.html` generated by CI is only a non-clinical fallback asset to let Capacitor sync. CI verifies that the generated native configuration actually points to the configured HTTPS origin before packaging.
- No patient data, credentials, signing certificates, provisioning profiles, or provider secrets are committed to the repository.

## Build outputs

The `.github/workflows/mobile-packaging.yml` workflow runs on a manual dispatch or changes to the mobile packaging contract on `main`.

### Android

- Artifact: `medlum-android-debug-apk`
- File: `app-debug.apk`
- This is a debug-signed APK suitable for direct test installation on an Android device after the user permits installation from the chosen source.
- It is not a Google Play production release. A release APK/AAB should use a separately managed Android release keystore and a deliberate release-signing workflow.

### iOS

- Artifact: `medlum-ios-simulator-app`
- Contains the compiled iOS Simulator `.app` bundle, zipped for download. This is for Simulator testing, not direct installation on a physical iPhone.
- Artifact: `medlum-ios-xcode-project`
- Contains the generated Xcode project for development, signing, and device testing.

A signed IPA can also be generated, but only after an Apple Developer signing setup is explicitly enabled. Configure the following GitHub repository settings:

- Repository variable `MEDLUM_IOS_SIGNING_ENABLED=true`
- Repository variable `MEDLUM_IOS_TEAM_ID` set to the Apple Developer Team ID
- Repository variable `MEDLUM_IOS_EXPORT_METHOD` set to `app-store-connect`, `ad-hoc`, `development`, or `enterprise`, matching the provisioning profile
- Repository secret `MEDLUM_IOS_CERTIFICATE_P12_BASE64` containing the base64-encoded Apple distribution/development certificate in P12 format
- Repository secret `MEDLUM_IOS_CERTIFICATE_P12_PASSWORD` containing that P12 password
- Repository secret `MEDLUM_IOS_PROVISIONING_PROFILE_BASE64` containing the base64-encoded provisioning profile for bundle ID `com.medlum.app`

When those settings are supplied, the workflow creates the `medlum-ios-signed-ipa` artifact. Keep signing credentials in GitHub's secrets manager; never commit them or paste them into source code, issues, or chat. An App Store Connect profile produces an IPA for App Store Connect/TestFlight upload, while Ad Hoc provisioning must include the intended test devices.

## Run or retrieve a build

1. Open the repository's **Actions → MedLum Mobile Packaging** workflow.
2. Select **Run workflow** and keep the default HTTPS URL (`https://medlumhealth.com`) unless intentionally building against another trusted HTTPS deployment.
3. Wait for the Android and iOS Simulator jobs to complete.
4. Open that workflow run and download the APK and iOS artifacts from **Artifacts**.
5. For physical iPhone installation or TestFlight/App Store distribution, configure the signing settings above and rerun the workflow.

A push to `main` that changes the mobile packaging workflow, Capacitor config, packaging verifier, or phase document also triggers a packaging run and attaches artifacts to the workflow run.

## Important production and distribution boundaries

- These are native Capacitor containers with embedded Android/iOS project code; the clinical UI is delivered from the HTTPS MedLum server. They are not separate Kotlin/Swift rewrites, and server-backed workflows still require connectivity.
- The workflow does not publish to Google Play or the Apple App Store. Store listing metadata, privacy disclosures, review, and distribution credentials remain separate release steps.
- Apple requires an appropriate signing certificate and provisioning profile for physical-device distribution. The Simulator build and Xcode project can be built without those credentials, but they are not a signed physical-device IPA.
- App Store review may require meaningful platform-specific value beyond a website wrapper. Before submission, validate native navigation/back behavior, external links, downloads/uploads, camera/file access, notifications if required, accessibility, and the applicable store policies.
- The workflow does not change the existing Render deployment or production database architecture. Clinical data continues to be served through the existing authenticated MedLum platform.
